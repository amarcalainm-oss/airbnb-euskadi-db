## Q01 - Nightly price by municipality

**Author:** Aitor Marcalain  
**Question:** Which municipalities are the most expensive per night, considering only municipalities with enough listings to be representative?  
**Techniques:** JOIN of 3 tables, GROUP BY + HAVING, ordered-set aggregate (percentile_cont)  
**Default parameters:** `{'province': None, 'room_type': None, 'min_listings': 20, 'top_n': 15}`

```sql
SELECT m.name                                     AS municipality,
       p.name                                     AS province,
       COUNT(*)                                   AS listings,
       ROUND(AVG(l.price), 2)                     AS avg_price,
       ROUND(percentile_cont(0.5) WITHIN GROUP (ORDER BY l.price)::numeric, 2) AS median_price
FROM airbnb.listing l
JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
JOIN airbnb.province     p ON p.province_id     = m.province_id
WHERE l.price IS NOT NULL
  AND (%(province)s  IS NULL OR p.name      = %(province)s)
  AND (%(room_type)s IS NULL OR l.room_type = %(room_type)s)
GROUP BY m.name, p.name
HAVING COUNT(*) >= %(min_listings)s
ORDER BY median_price DESC
LIMIT %(top_n)s;
```

## Q03 - Monthly demand trend (reviews per month, year-over-year)

**Author:** Aitor Marcalain  
**Question:** How has the number of reviews per month evolved, and how does each month compare with the same month of the previous year?  
**Techniques:** CTE chain, generate_series to fill months with no reviews, COUNT(DISTINCT), window function LAG(..., 12)  
**Default parameters:** `{'province': None, 'year_from': 2016}`

```sql
WITH monthly AS (
    SELECT date_trunc('month', r.review_date)::date AS month,
           COUNT(DISTINCT r.review_id)              AS reviews
    FROM airbnb.review r
    JOIN airbnb.listing_review lr ON lr.review_id      = r.review_id
    JOIN airbnb.listing        l  ON l.listing_id      = lr.listing_id
    JOIN airbnb.municipality   m  ON m.municipality_id = l.municipality_id
    JOIN airbnb.province       p  ON p.province_id     = m.province_id
    WHERE (%(province)s IS NULL OR p.name = %(province)s)
    GROUP BY 1
),
all_months AS (
    SELECT gs::date AS month, COALESCE(mo.reviews, 0) AS reviews
    FROM generate_series((SELECT MIN(month) FROM monthly),
                         (SELECT MAX(month) FROM monthly), INTERVAL '1 month') gs
    LEFT JOIN monthly mo ON mo.month = gs::date
),
with_last_year AS (
    SELECT month, reviews, LAG(reviews, 12) OVER (ORDER BY month) AS reviews_last_year
    FROM all_months
)
SELECT month, reviews, reviews_last_year,
       ROUND(100.0 * (reviews - reviews_last_year) / NULLIF(reviews_last_year, 0), 1) AS yoy_change_pct
FROM with_last_year
WHERE month >= make_date(%(year_from)s, 1, 1)
ORDER BY month;
```

## Q06 - Price premium of each amenity

**Author:** Iker Elias  
**Question:** Which amenities are associated with a higher price per guest, comparing listings that have them with those that do not?  
**Techniques:** CTE chain, JOIN through the N:M bridge table, GROUP BY + HAVING, CROSS JOIN with totals  
**Default parameters:** `{'province': None, 'room_type': None, 'min_listings': 100, 'top_n': 15}`

```sql
WITH base AS (
    SELECT l.listing_id, l.price / l.accommodates AS price_per_guest
    FROM airbnb.listing l
    JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
    JOIN airbnb.province     p ON p.province_id     = m.province_id
    WHERE l.price IS NOT NULL
      AND (%(province)s  IS NULL OR p.name      = %(province)s)
      AND (%(room_type)s IS NULL OR l.room_type = %(room_type)s)
),
overall AS (
    SELECT COUNT(*) AS n_all, SUM(price_per_guest) AS sum_all
    FROM base
),
with_amenity AS (
    SELECT a.name AS amenity, COUNT(*) AS n_with, SUM(b.price_per_guest) AS sum_with
    FROM base b
    JOIN airbnb.listing_amenity la ON la.listing_id = b.listing_id
    JOIN airbnb.amenity         a  ON a.amenity_id  = la.amenity_id
    GROUP BY a.name
    HAVING COUNT(*) >= %(min_listings)s
),
both_groups AS (
    SELECT w.amenity,
           w.n_with,
           o.n_all - w.n_with                                       AS n_without,
           w.sum_with / w.n_with                                    AS avg_with,
           (o.sum_all - w.sum_with) / NULLIF(o.n_all - w.n_with, 0) AS avg_without
    FROM with_amenity w CROSS JOIN overall o
)
SELECT amenity,
       n_with                                   AS listings_with,
       n_without                                AS listings_without,
       ROUND(avg_with, 2)                       AS avg_price_guest_with,
       ROUND(avg_without, 2)                    AS avg_price_guest_without,
       ROUND(100.0 * (avg_with / avg_without - 1), 1) AS premium_pct
FROM both_groups
WHERE n_without >= %(min_listings)s
ORDER BY premium_pct DESC
LIMIT %(top_n)s;
```

## Q07 - Superhosts vs regular hosts

**Author:** Iker Elias  
**Question:** Do listings run by superhosts really get better guest scores than those of regular hosts, in each province?  
**Techniques:** JOIN, GROUP BY, correlated subquery in WHERE, CASE  
**Default parameters:** `{'min_reviews': 10}`

```sql
SELECT p.name                                                            AS province,
       CASE WHEN h.is_superhost THEN 'Superhost' ELSE 'Regular host' END AS host_type,
       COUNT(*)                                                          AS listings,
       ROUND(AVG(l.score_rating), 3)                                     AS avg_rating,
       ROUND(AVG(l.score_cleanliness), 3)                                AS avg_cleanliness,
```

## Q08 - Weekend vs weekday unavailability by municipality

**Author:** Iker Elias  
**Question:** In which municipalities are Friday and Saturday nights unavailable (booked or blocked by the host) much more often than weekday nights over the coming weeks?  
**Techniques:** CTE, scalar subquery, aggregate FILTER, EXTRACT(ISODOW), GROUP BY + HAVING, window function RANK()  
**Default parameters:** `{'province': None, 'horizon_days': 90, 'min_listings': 30, 'top_n': 15}`

```sql
WITH nights AS (
    SELECT m.name AS municipality, p.name AS province, c.listing_id,
           EXTRACT(ISODOW FROM c.day) IN (5, 6) AS is_weekend,
           NOT c.available                      AS is_unavailable
    FROM airbnb.calendar_day c
    JOIN airbnb.listing      l ON l.listing_id      = c.listing_id
    JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
    JOIN airbnb.province     p ON p.province_id     = m.province_id
    WHERE c.day < (SELECT MIN(day) FROM airbnb.calendar_day) + %(horizon_days)s
      AND (%(province)s IS NULL OR p.name = %(province)s)
),
occ AS (
    SELECT municipality, province,
           COUNT(DISTINCT listing_id) AS listings,
           100.0 * COUNT(*) FILTER (WHERE is_weekend AND is_unavailable)
                 / COUNT(*) FILTER (WHERE is_weekend)                 AS weekend_occ,
           100.0 * COUNT(*) FILTER (WHERE NOT is_weekend AND is_unavailable)
                 / COUNT(*) FILTER (WHERE NOT is_weekend)             AS weekday_occ
    FROM nights
    GROUP BY municipality, province
    HAVING COUNT(DISTINCT listing_id) >= %(min_listings)s
)
SELECT RANK() OVER (ORDER BY weekend_occ - weekday_occ DESC) AS rank,
       municipality, province, listings,
       ROUND(weekend_occ, 1)               AS weekend_occ_pct,
       ROUND(weekday_occ, 1)               AS weekday_occ_pct,
       ROUND(weekend_occ - weekday_occ, 1) AS gap_points
FROM occ
ORDER BY rank
LIMIT %(top_n)s;
```

## Q09 - What-if: price change in a municipality (UPDATE inside a transaction)

**Author:** Aitor Marcalain  
**Question:** If every listing in a municipality changed its price by X %, how would the municipality's average and median price change?  
**Techniques:** transaction (BEGIN ... ROLLBACK), UPDATE ... FROM with a join, aggregates before/after  
**Default parameters:** `{'municipality': 'Donostia-San Sebastián', 'pct_change': 10}`

```sql
-- @step before
SELECT 'before' AS moment, COUNT(l.price) AS listings_with_price,
       ROUND(AVG(l.price), 2) AS avg_price,
       ROUND(percentile_cont(0.5) WITHIN GROUP (ORDER BY l.price)::numeric, 2) AS median_price
FROM airbnb.listing l JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
WHERE m.name = %(municipality)s;
-- @step update
UPDATE airbnb.listing l
SET price = ROUND(l.price * (1 + %(pct_change)s / 100.0), 2)
FROM airbnb.municipality m
WHERE m.municipality_id = l.municipality_id
  AND m.name = %(municipality)s
  AND l.price IS NOT NULL;
-- @step after
SELECT 'after' AS moment, COUNT(l.price) AS listings_with_price,
       ROUND(AVG(l.price), 2) AS avg_price,
       ROUND(percentile_cont(0.5) WITHIN GROUP (ORDER BY l.price)::numeric, 2) AS median_price
FROM airbnb.listing l JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
WHERE m.name = %(municipality)s;
```

**Sample result:**

| moment | listings_with_price | avg_price | median_price |
|---|---|---|---|
| before | 1395 | 290.58 | 228.00 |
| after | 1395 | 319.64 | 250.80 |

_UPDATE affected 1395 rows; the transaction then ended with ROLLBACK._

**Why it is meaningful:** It runs a real UPDATE inside a transaction, measures the effect and then ROLLBACKs, so the database is never left modified: a safe "simulation" mode.

**Author:** Iker Elias  
**Question:** How many guests come back and write more than one review in Euskadi, and how many days pass on average between their consecutive reviews?  
**Techniques:** CTE, window function LEAD() OVER (PARTITION BY ... ORDER BY ...), GROUP BY, window over an aggregate (SUM(COUNT(*)) OVER ())  
**Default parameters:** `{'year_from': 2011}`

```sql
WITH rv AS (
    SELECT r.reviewer_id, r.review_date,
           LEAD(r.review_date) OVER (PARTITION BY r.reviewer_id ORDER BY r.review_date, r.review_id) AS next_review_date
    FROM airbnb.review r
    WHERE r.review_date >= make_date(%(year_from)s, 1, 1)
),
per_reviewer AS (
    SELECT reviewer_id, COUNT(*) AS n_reviews, AVG(next_review_date - review_date) AS avg_gap_days
    FROM rv
    GROUP BY reviewer_id
)
SELECT CASE WHEN n_reviews >= 5 THEN '5+' ELSE n_reviews::text END AS reviews_written,
       COUNT(*)                                                 AS reviewers,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2)        AS pct_reviewers,
       ROUND(AVG(avg_gap_days))                                 AS avg_days_between_reviews
FROM per_reviewer
GROUP BY 1
ORDER BY MIN(n_reviews);
```

## Q11 - Tourist-registry licence status by municipality

**Author:** Aitor Marcalain  
**Question:** In which municipalities is the share of listings without any registration number highest?  
**Techniques:** JOIN, GROUP BY + HAVING, aggregate FILTER, pattern matching (ILIKE)  
**Default parameters:** `{'province': None, 'room_type': None, 'min_listings': 20, 'top_n': 15}`

```sql
SELECT m.name                                                              AS municipality,
       p.name                                                              AS province,
       COUNT(*)                                                            AS listings,
       COUNT(*) FILTER (WHERE l.license IS NOT NULL AND l.license NOT ILIKE '%%exempt%%') AS registered,
       COUNT(*) FILTER (WHERE l.license ILIKE '%%exempt%%')                AS exempt,
       COUNT(*) FILTER (WHERE l.license IS NULL)                           AS no_license,
       ROUND(100.0 * COUNT(*) FILTER (WHERE l.license IS NULL) / COUNT(*), 1) AS pct_no_license
FROM airbnb.listing l
JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
JOIN airbnb.province     p ON p.province_id     = m.province_id
WHERE (%(province)s  IS NULL OR p.name      = %(province)s)
  AND (%(room_type)s IS NULL OR l.room_type = %(room_type)s)
GROUP BY m.name, p.name
HAVING COUNT(*) >= %(min_listings)s
ORDER BY pct_no_license DESC, listings DESC
LIMIT %(top_n)s;
```

## Q12 - Best-value listings (cheaper than their town, top rated)

**Author:** Iker Elias  
**Question:** Which well-reviewed listings are cheaper than the median price of their own municipality while keeping a very high value score?  
**Techniques:** two CTEs (median per group with percentile_cont, reviews per listing), JOIN, computed comparison columns  
**Default parameters:** `{'province': None, 'room_type': 'Entire home/apt', 'min_score': 4.8, 'min_reviews': 20, 'top_n': 20}`

```sql
WITH town_median AS (
    SELECT municipality_id, room_type,
           percentile_cont(0.5) WITHIN GROUP (ORDER BY price)::numeric AS median_price
    FROM airbnb.listing
    WHERE price IS NOT NULL
    GROUP BY municipality_id, room_type
    HAVING COUNT(*) >= 10
),
review_counts AS (
    SELECT listing_id, COUNT(*) AS n_reviews
    FROM airbnb.listing_review
    GROUP BY listing_id
)
SELECT l.listing_id, l.name AS listing, m.name AS municipality, l.room_type,
       l.price,
       ROUND(tm.median_price, 2)                       AS town_median_price,
       ROUND(100 * (l.price / tm.median_price - 1), 1) AS pct_vs_town_median,
       l.score_value, l.score_rating,
       rc.n_reviews
FROM airbnb.listing l
JOIN town_median         tm ON tm.municipality_id = l.municipality_id AND tm.room_type = l.room_type
JOIN review_counts       rc ON rc.listing_id      = l.listing_id
JOIN airbnb.municipality m  ON m.municipality_id  = l.municipality_id
JOIN airbnb.province     p  ON p.province_id      = m.province_id
WHERE l.price < tm.median_price
  AND l.score_value >= %(min_score)s
  AND rc.n_reviews  >= %(min_reviews)s
  AND (%(province)s  IS NULL OR p.name      = %(province)s)
  AND (%(room_type)s IS NULL OR l.room_type = %(room_type)s)
ORDER BY l.score_value DESC, pct_vs_town_median ASC, l.listing_id
LIMIT %(top_n)s;
```

## Q13 - Map of listings by price quintile

**Author:** Aitor Marcalain  
**Question:** Where are the listings located, and where are the cheapest and the most expensive fifths of the market concentrated?  
**Techniques:** JOIN, window functions NTILE(5) and MIN/MAX OVER (PARTITION BY), subquery in FROM  
**Default parameters:** `{'province': None, 'room_type': None, 'min_reviews': 0}`

```sql
SELECT q.listing_id, q.listing, q.municipality, q.room_type, q.price, q.score_rating,
       q.latitude, q.longitude, q.price_quintile,
       'Q' || q.price_quintile || ': ' ||
       MIN(q.price) OVER (PARTITION BY q.price_quintile) || ' - ' ||
       MAX(q.price) OVER (PARTITION BY q.price_quintile) || ' EUR'      AS price_band
FROM (
    SELECT l.listing_id, l.name AS listing, m.name AS municipality, l.room_type, l.price,
           l.score_rating, l.latitude, l.longitude,
           NTILE(5) OVER (ORDER BY l.price) AS price_quintile
    FROM airbnb.listing l
    JOIN airbnb.municipality m ON m.municipality_id = l.municipality_id
    JOIN airbnb.province     p ON p.province_id     = m.province_id
    WHERE l.price IS NOT NULL
      AND (%(province)s  IS NULL OR p.name      = %(province)s)
      AND (%(room_type)s IS NULL OR l.room_type = %(room_type)s)
      AND (SELECT COUNT(*) FROM airbnb.listing_review lr WHERE lr.listing_id = l.listing_id) >= %(min_reviews)s
) q
ORDER BY q.price_quintile, q.price;
```
